# Glossaire

Vocabulaire à employer tel quel dans le code, la documentation, les issues et les comptes rendus d'agents. Un terme nouveau ou précisé est ajouté par `architect`.

## Domaine

- **Table d'expérience** : table construite à partir des observations du portefeuille lui-même (par opposition à une table réglementaire ou de référence), qui donne, pour un risque, la probabilité ou le taux de l'événement selon un ou plusieurs axes (âge, ancienneté, année). *Ne pas dire* : table de mortalité (cas particulier : le risque décès), table interne, table maison.
- **Table du moment** : table d'expérience à un seul axe principal (l'âge, ou l'ancienneté), estimée sur une période d'observation et sans dimension d'année calendaire. *Ne pas dire* : table statique, table périodique, table transversale.
- **Table prospective** : table d'expérience à deux axes, l'âge et l'année calendaire, qui incorpore l'évolution attendue du risque dans le temps ; une table de génération en est la diagonale pour une année de naissance. *Ne pas dire* : table dynamique, table générationnelle (pour désigner la surface entière).
- **Amélioration de la mortalité** : la baisse attendue des taux de décès d'une année à l'autre, à âge donné ; représentée soit par une échelle d'amélioration appliquée à une table de base (pratique américaine et britannique : échelles MP de la SOA, modèle CMI), soit par un modèle conjoint âge-année (Lee-Carter et dérivés). *Ne pas dire* : dérive de mortalité, tendance (sans qualificatif).
- **Transition** : le passage d'un état de départ à un état d'arrivée (vivant → décédé, en cours → racheté, en incapacité → sorti), dont une table d'expérience estime le taux selon un axe principal (âge ou ancienneté), avec des sorties concurrentes et une censure. Tout risque de l'outil est une transition ou un ensemble de transitions. *Ne pas dire* : sinistre, événement (sans préciser la transition).
- **Surface de mortalité** : l'objet q_{x,t} par âge et année calendaire, produit indifféremment par un modèle conjoint (Lee-Carter et dérivés) ou par la combinaison d'une table de base et d'une échelle d'amélioration ; toute table prospective en est une. *Ne pas dire* : matrice de mortalité, table 2D.
- **Rapport figé** : le document HTML autonome, sans ressource externe, qui restitue une construction telle que le moteur l'a retournée, sans recalcul, avec ses empreintes. *Ne pas dire* : export, rapport dynamique, snapshot.
- **Plan de construction** : la suite ordonnée des étapes (exposition, taux bruts, lissage ou positionnement, fermeture, validation, table) et de leurs paramètres, que le moteur exécute en une seule fois ; comparer des méthodes, c'est exécuter plusieurs plans sur les mêmes données. *Ne pas dire* : workflow, scénario, pipeline.
- **Fiche de construction** : la description lisible par machine d'une construction — plan de construction, empreinte des données, rôles des variables, convention d'âge et recette retenues, graine, versions — qui suffit à la rejouer à l'identique. *Ne pas dire* : configuration, paramétrage, log.
- **Rôle** : la nature, déclarée par l'utilisateur, d'une colonne de la base (identifiant de tête, date de naissance, cause de sortie, exposition…), prise dans un catalogue fermé ; le moteur ne lit une colonne que par son rôle. *Ne pas dire* : type de colonne, mapping, champ.
- **Recette d'exposition** : la méthode par laquelle le moteur calcule l'exposition et compte les événements à partir des rôles présents ; il retient la plus fine que les rôles permettent, la nomme dans le rapport, et refuse si aucune ne s'applique. *Ne pas dire* : mode de calcul, algorithme d'exposition.
- **Convention d'âge** : la règle de calcul de l'âge qu'une recette applique : âge au dernier anniversaire (dates complètes), âge atteint dans l'année (année − année de naissance), âge fourni ; l'utilisateur peut forcer une convention plus grossière que celle déduite. *Ne pas dire* : âge exact, âge réel.
- **Tête** : la personne assurée ; unité d'observation dès qu'un identifiant de tête est déclaré, le moteur fusionnant les intervalles d'observation de ses contrats ; à défaut, l'unité est le **contrat**, avec avertissement. *Ne pas dire* : assuré (ambigu entre la personne et le contrat), police, ligne.
- **Période d'observation** : l'intervalle, déclaré par l'utilisateur et jamais déduit des données, pendant lequel les événements sont observés. *Ne pas dire* : fenêtre, historique, profondeur.
- **Délai de déclaration** : la durée déclarée qui tronque la fin de la période d'observation pour écarter les événements survenus mais pas encore connus. *Ne pas dire* : IBNR (l'estimation des événements tardifs est une autre opération), retard.
- **Troncature à gauche** : le fait qu'une tête n'est observée qu'à partir de son entrée en observation, postérieure à sa naissance ; **censure à droite** : la fin d'observation d'une tête sans l'événement étudié (sortie pour une autre cause, fin de période). Toute recette d'exposition les traite explicitement. *Ne pas dire* : données incomplètes (sans préciser), perdus de vue.
- **Segment** : la sous-population définie par les variables de segmentation déclarées (le sexe ; une variable libre en v1) ; l'absence de segmentation est un choix explicite. *Ne pas dire* : strate, classe, cohorte (réservé à une année de naissance).
- **Table unique** : table sans distinction de sexe, obtenue par combinaison des tables par sexe selon une pondération déclarée, ou par estimation sur la population regroupée ; la voie et la pondération figurent dans la fiche. *Ne pas dire* : table unisexe, table mixte.
- **Table de référence** : table externe sur laquelle une table d'expérience est positionnée ou à laquelle elle est comparée. **Table homologuée** : table de référence prescrite par arrêté (TD/TV 88-90, TH/TF 00-02, TGH05/TGF05, table unique 2024). **Table certifiée** : table d'expérience certifiée par un actuaire indépendant agréé. *Ne pas dire* : table réglementaire (pour une table de l'INSEE ou de l'Institut des actuaires, qui n'est pas homologuée).
- **Suivi d'expérience** : la comparaison d'une table quelconque — construite, homologuée, certifiée — à de nouvelles observations (ratio observés / attendus global et par sous-groupes, SMR, signes, runs, intervalles de confiance) ; répond au suivi annuel de certification et au backtesting de l'orientation 87. *Ne pas dire* : backtesting (sans préciser l'objet), monitoring.
- **Indicateur de suffisance** : une grandeur (exposition et événements par âge, largeur d'intervalle de confiance) qui signale ce que les données portent ou non ; il n'interdit aucune méthode. *Ne pas dire* : seuil de validité, critère d'éligibilité.
- **Marge** : l'étape du plan de construction qui applique la prudence à la table (abattement ou majoration des taux, ou quantile de l'incertitude), toujours par un paramètre déclaré ; une marge nulle est un paramètre comme un autre. *Ne pas dire* : chargement de sécurité, prudence (sans qualificatif).
- **Loi vraie** : la table de référence et les facteurs par segment dont le simulateur tire un jeu de données ; seule vérité disponible pour les tests, portée par chaque jeu versionné avec sa graine. *Ne pas dire* : vraie table, table théorique.
- **Fichier de provenance** : le fichier versionné à côté d'une table de référence embarquée (source, URL, date de consultation, licence, empreintes, méthode de transcription, contre-vérification). *Ne pas dire* : métadonnées, readme de la table.
- **Contre-vérification** : une valeur de référence externe (package avancé hors moteur, seconde source, seconde transcription) écrite en dur dans un test avec sa version et sa date, produite hors CI. *Ne pas dire* : test croisé, benchmark.

## Organisation du travail

- **Branche de travail** : l'unique branche `claude/…` en cours, au périmètre fermé d'issues, portée par une PR brouillon vers `main`.
- **Correctif rapide** : modification hors périmètre qui laisse les résultats strictement identiques, touche un seul domaine de commit et pas la documentation de fond ; branche temporaire partie de `main`, PR directe.
- **Tableau avant / après** : pour un commit qui change un résultat, une ligne par grandeur modifiée (avant, après, écart, explication).
- **Visa** : approbation d'un tableau avant / après — par le mainteneur pour un résultat final ou un verdict, par `actuary` sinon. Sans visa, rien n'est commité.
- **Surface d'impact documentaire** : liste, dans le commit proposé par `coder`, des endroits de la documentation que la modification oblige à rouvrir ; point de départ de `docwriter`.
- **Constat** : défaut du code relevé par un vérificateur, avec gravité (bloquant / majeur / mineur), `fichier:ligne` et mesure exécutée. Conduit à une reprise ou à un arrêt.
- **Question pour `actuary`** (ou pour `regulatory`, quand elle porte sur un texte) : doute sur le fond, qui n'est pas un défaut du code ; ne relance pas `coder`.
- **Audit léger** : lecture du diff et des fonctions touchées avec leurs appelants et appelés.
- **Revue finale complète** : lecture de tout `git diff main...HEAD`, batteries complètes et scénarios adverses, avant la sortie du brouillon.
- **Mesure** : commande exécutée et sa sortie, qui fonde une affirmation sur le comportement du code.
- **Consultation** : un appel d'un agent de pilotage ou de fond par la session principale ; se termine par un bloc « Retour » (statut `complet`, `partiel` ou `revue requise`).
- **Routine / jugement** : les deux niveaux d'une consultation d'`architect`, d'`actuary` ou de `regulatory` — fiche de base (Opus, effort `medium`) ou fiche `-approfondi` (Opus, effort `high`) ; voir `docs/agents/routage.md`.
- **Escalade** : passage d'une consultation à un niveau supérieur, hausse d'effort (routine → jugement) ou changement de modèle (Opus → Fable), sur un critère observable ; distincte de la **relance ciblée** (même agent, même fiche, retour incomplet) et de la demande d'information.
- **Question** (routage) : la question résiduelle d'une consultation, rattachée à une issue ou à une mission ; unité des plafonds de `docs/agents/routage.md` (§ 5.2) ; la reformuler ne remet pas ses plafonds à zéro.
- **Dossier d'escalade** : question résiduelle, contraintes, conclusions établies, sources, tentatives, contradictions et preuve attendue, transmis à la consultation suivante pour éviter une nouvelle revue globale.
